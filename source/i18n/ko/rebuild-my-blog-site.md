## 1 옛 블로그

나의 옛 블로그는 `hexo`로 구축했다. `hexo`는 사용하기 매우 간단하고 비교적 풍부한 생태계도 갖추고 있다. 그럼에도 나는 나의 블로그를 위해 유사한 정적 사이트 생성기를 직접 작성하기로 결정했는데, 이유는 비교적 간단하다:
- `hexo`의 기본 기능은 적고, 많은 기능을 플러그인으로 구현해야 하는데 플러그인의 품질과 안전성이 들쭉날쭉하다
- 플러그인으로 구현되지 않은 기능은 직접 *nodejs* 플러그인을 작성해야 하는데, *TypeScript*를 도저히 쓰고 싶지 않았다(forgive me😵)
- 정적 사이트를 생성하는 것도 꽤 재미있는데, 속이 알차면서도 작고 정교한 생성기를 직접 구현하지 않을 이유가 있겠는가

무려 1년에 걸친 마라톤 끝에, base 테마를 제외하면 Rust 부분은 모두 전통적인 코딩 방식으로 틈틈이 시간을 내어 조금씩 작성했다. 최종적으로 나의 대부분의 비전을 충족하는 [`tles` v0.2](https://github.com/iskyrainy/tless/releases/tag/v0.2.1)를发布했다.

`tokei`로 코드량을 집계해보니 4000줄이 채 안 되어, 대략 `hexo`의 10% 정도에 불과하다:

아래는 나의 최초 비전 기능 설계와 일부 구현에 대한 고민과 선택의 과정이다.

## 2 최초 설계

### 2.1 기본 기능
나는 이전에 계속 `hexo`를 사용해왔기 때문에, 최초의 기준점은 `hexo`였고, 가장 기본적인 기능은 다음과 같다:
- Markdown과 같은 경량 마크업 언어를 지원하고 `HTML` 정적 페이지로 렌더링
- 사용자 정의 테마
- 사용자 정의 플러그인
- 초안과 발행
- 개발 API와 핫 리로드
- 간단하고 사용하기 쉬운 명령줄
- Github Pages 배포 지원

### 2.2 tles 확장 내장 기능
[2.1](#21-기본-기능)은 정적 사이트 생성기의 기본적이지만 핵심적인 기능으로, 전체적으로는: Markdown을 작성하고, 발행하고, HTML을 렌더링하는 것이다. 물론 이것들 외에도 매우 실용적인 기능 일부를 내장하고 싶었는데, 예를 들어 네이티브 *SEO* 최적화, 내장 국제화, 네이티브 사이트 분석 연동 등이다. 구체적인 내용은 아래 목록을 참고하라:
- **내장 SEO 최적화**: Atom 프로토콜 지원, `atom.xml`, `sitemap.xml` 자동 생성
- **내장 LLM 국제화**: 예전에는 국제화가 쉽지 않아서, 하나의 블로그를 여러 언어로 반복 작성하자니 너무 힘들고, 번역 엔진 API를 호출하자니 기계 번역의 품질이 불안정했다. 하지만 지금은 AI LLM 시대이므로, 저렴한 API로 수준 높은 국제화 번역을 충분히 구현할 수 있다🤠
- **내장 giscus 지원**: 블로그를 쓰는 데 가장 중요한 것은 공유와 교류다
- **내장 사이트 분석 연동**: Google/Bing Analysis 또는 기타 사이트 분석 도구를 통해 사이트 트래픽을 기록하고 분석
- **비공개 블로그**: 생활을 기록하는 일부 블로그는 공개하기에 적합하지 않을 수 있어서 우연히 이 아이디어가 떠올랐지만, 정적 사이트 생성기에게는 다소 상극이다
- **크로스 플랫폼 프런트엔드**: 언제 어디서나 현대적이고 사용하기 쉬운 프런트엔드 APP/web을 통해 블로그 작성

아이디어는 많지만, 그중 일부 기능은 분명히 정적 사이트 속성과 상충한다. 예를 들어 *비공개 블로그*가 그렇다. 비공개인 이상 반드시 동적 인증이 필요하고, 개발 모드에서는 구현할 수 있겠지만 Github나 Cloudflare에 배포하면 비공개라는 개념 자체가 존재하지 않게 된다.

> 이 부분 기능은 지금까지도 구상 중이며, 현재의 미성숙한 아이디어는 자체 호스팅 블로그 서비스만 지원하고 정적 프록시에서는 기본적으로 비공개 블로그를 렌더링하지 않는 것이다. 더 많은 정보는 계속해서 [#20](https://github.com/iskyrainy/tless/issues/20)을关注해 주기 바란다.
