## 必ず生まれ、やがて没落する
インターネット精神、なんと美しい言葉だろう。「精神」の名を冠した言葉はどれも、耳にした瞬間に輝かしい未来、純粋な理想郷が目に浮かぶようだ。しかもインターネット精神は表面的な「精神」という名にとどまらない。その「開放、自由、協働、共有」という内核と実践が、インターネットの黄金時代を形作った。

人類史上の思想解放と知識普及の運動と比べても、インターネット精神の誕生にはどこか通じるものがあり、ほとんど歴史がデジタル時代に再演されたかのようだ。自由ソフトウェア運動（Free Software Movement）は、ユーザーがソフトウェアを使用・複製・研究・改変・配布する権利を推進する社会運動であり、その究極の理念はネットワーク上のあらゆる人（コンピュータユーザー）を解放することにある。無数の自由を愛する者たちが、中世に教会を建てた工匠のように、レンガを一つ一つ積み上げてインターネットの大厦を築いた。オープンソースコードの「クラウドソーシング」モデルは、思想の共有と生産力の共有を統一する。これは啓蒙運動の「知識は力であり、力は公衆に帰すべき」という内核とまったく同じだ。

初期のインターネットは高い参入障壁に限られていたため、ユーザーはおおむね高学歴・高教育の人々であり、彼らは主観的に権威と専制に反対し、中央集権的な権力（大企業）に操られることを望まなかった。彼らはコンピュータの領域で「技術的無政府主義」を実現し、各コンピュータ利用者が一点に集中するのではなく自由な権利を持つことを希求した。

結局のところ自由意識は生物の遺伝子多様性の副産物にすぎず、その本質は大脳による原始的本能の抑制である。そして生物学的な遺伝子多様性の進化目標は生存と繁殖であり、それに対応するのは生物が本能的に利益を求め害を避けることだ。インターネット精神は必然であると同時に偶然でもある。必然とは、発展に伴い必ずそれを信仰し追求する者が現れるということであり、偶然とは、そのために代価を払うことを望む者は少数にとどまるということだ。

インターネット精神の誕生はインターネットの隆盛を促し、一般大衆がコンピュータを使いインターネットの便利さを享受できるようにした。しかし、すべての個人にインターネット精神の代価――満足の先延ばし、不確実性の受容、調整コストの負担――を負わせることを求めるのは、結局は絵に描いた餅であることが証明された。商業資本は、人間の天性の奥深くに刻まれた怠惰と安逸という基底コードに沿って、茹でガエルのようにゆっくりと調理し、飴玉でユーザーを彼らの区画した一亩三分の地へと導いていく。

「開放、自由、協働、共有」という内核は、そのどれもが商業の神経の上で踊っている。疑いなく、インターネット精神は刻一刻と商業資本の利益を損なっている。これはオイディプスのような宿命であり、あの巨大な商業プラットフォーム（Google、Meta）こそ、まさにインターネット精神の初期の産物である。彼らは開放的なTCP/IP、オープンソースコード、そしてグローバルな協働を利用して築き上げられた。しかし彼らがインターネットの中心へと成長した後は、生存と決算報告のために、開放精神を裏切り、閉鎖的な障壁を作り出すのは必然なのだ。

これには面白い話もある。昨年、会社のイベントで某区の人工知能研究院を視察した。イベント最後の講演会で、講演者は中米のLLMモデルの差に触れ、その大きな原因の多くは中国語インターネット上にゴミが多すぎて高品質な学習資料が乏しいためだと痛心して述べた。それを聞いて、私はどこかユーモラスでどこか皮肉に感じた。「あなたはインターネット上で縄張りを張って儲けるときだけ、このインターネットが好きなわけにはいかないだろう」。古き中国語インターネットの「開放・平等・共有」の気風は、まさにあなたがた商業会社によって破壊されたのではないか？その中で最もユーモラスな例は、百度が数度にわたって大規模に貼吧のデータを消去したことだろう。目先しか見えないことがうかがえるし、現実の事実も、BATの中で百度だけがますます没落していることを証明している。そして今、インターネットの発展がボトルネックに直面する一方でLLM AIが大規模に興起しているのに、中国語インターネットが高品質なデータを提供できないと責めるとは、まったくもって荒唐無稽である。では問いたい、今インターネット上にあふれるゴミデータはどのように生まれたのか、そして誰がこのような状況へと導いたのか？

> ちなみに、講演者にはもう一つ間違いがある。今年の中国のLLMの発展状況も証明しているように、高性能なLLMを作れないのは純粋に実力不足（字節跳動、騰訊、そして某為も含む。申し訳ないが、この会社だけは名前を直接呼ぶ勇気がない）であり、中国語インターネットがどうであるかとは何の関係もない。

## RSSの美は、共有にある
RSS（Really Simple Syndication、簡易コンテンツ集約）はWeb 1.0時代に生まれ、ユーザーがサイトを一つ一つ訪れることなく、一つのリーダーで自由に異なる来源の情報更新を購読・集約できるようにすることを目的としていた。それはごく簡潔なプロトコル内容しか持たないが、**開放**的かつ**平等**的にコンテンツをすべての購読者に配信し、人類の知識と認知を共有・共建し、「開放ゆえに自由、自由が自由な協働を生み、協働が最後に共有を生み、共有がまた開放を生む」という生生不息たるインターネット精神を完璧に体現している。

しかし明らかにRSSは、商業インターネットの縄張り争いとは極めて対極にある。RSSは開放的で脱中心化しており、サイトを迂回して直接コンテンツを取得し広告を伴わないそのモデルは、商業会社にトラフィックと広告収入をもたらすことができず、自然と辺縁化された。現在でも一部の会社／組織／個人が維持するシステムはRSSによるコンテンツ配信をサポートしているが、それ以上のコンテンツは商業インターネットによって隔離され、自由なコンテンツ配信をサポートしないばかりか、厳格に反クローラーでデータを隔離している。

このブログでは主に、自らデプロイでき、万物を自由に配信できるRSSアーキテクチャの一式を紹介したい。主に以下を含む：
- ネイティブでRSS/Atomプロトコルをサポートするコンテンツ；
- 自由な配信をサポートしないコンテンツ；
- 安全な自デプロイアーキテクチャ；

### コンテンツをどう配信するか
[RSSHub](https://docs.rsshub.app/zh/)は世界最大のRSSネットワークと謳われ、その目標は万物皆RSS化可能であることだ。RSSHubは対応するルートを書くだけで、各社の囲い込まれた庭園内のコンテンツをRSSフィードに変換し、それをRSSリーダーに渡して閲覧することができる。

公式のRSSHubを使用すると、コンテンツを所有する会社の反クローラー戦略を発動させる可能性があるため、自デプロイがより推奨される方式だ。公式のデプロイ文書に基づき、私は自デプロイの負担をできるだけ減らし、性能を高めデプロイの簡易さを向上させるため、いくつか簡略化を行った。

個人的には`docker-compose`でRSSHubをデプロイし、`redis`キャッシュを使って使用体験を向上させることを勧める。`browserless/chrome`をデプロイするかどうかは個人のニーズに応じて選ぶとよい。

`browserless/chrome`なしの`docker-compose.yaml`は以下の通り：
```bash
services:
    rsshub:
        image: diygod/rsshub # or ghcr.io/diygod/rsshub
        restart: always
        ports:
            - '1200:1200'
        environment:
            ALLOW_ORIGIN: '*'
            NODE_ENV: production
            CACHE_TYPE: redis
            REDIS_URL: 'redis://redis:6379/'
        healthcheck:
            test: ['CMD', 'curl', '-f', 'http://localhost:1200/healthz']
            interval: 30s
            timeout: 10s
            retries: 3
        depends_on:
            - redis

    redis:
        image: redis:alpine
        restart: always
        volumes:
            - redis-data:/data
        healthcheck:
            test: ['CMD', 'redis-cli', 'ping']
            interval: 30s
            timeout: 10s
            retries: 5
            start_period: 5s

volumes:
    redis-data:

```

`browserless/chrome`が必要な場合は公式提供のyamlを参照し、クロスオリジンを許可することを忘れないように：
```bash
services:
    rsshub:
        # two ways to enable Playwright:
        # * comment out marked lines, then use this image instead: diygod/rsshub:chromium-bundled
        # * (consumes more disk space and memory) leave everything unchanged
        image: diygod/rsshub # or ghcr.io/diygod/rsshub
        restart: always
        ports:
            - '1200:1200'
        environment:
            ALLOW_ORIGIN: '*'
            NODE_ENV: production
            CACHE_TYPE: redis
            REDIS_URL: 'redis://redis:6379/'
            PLAYWRIGHT_WS_ENDPOINT: 'ws://browserless:3000' # marked
        healthcheck:
            test: ['CMD', 'curl', '-f', 'http://localhost:1200/healthz']
            interval: 30s
            timeout: 10s
            retries: 3
        depends_on:
            - redis
            - browserless # marked

    browserless: # marked
        image: browserless/chrome # marked
        restart: always # marked
        ulimits: # marked
            core: # marked
                hard: 0 # marked
                soft: 0 # marked
        healthcheck: # marked
            test: ['CMD', 'curl', '-f', 'http://localhost:3000/pressure'] # marked
            interval: 30s # marked
            timeout: 10s # marked
            retries: 3 # marked

    redis:
        image: redis:alpine
        restart: always
        volumes:
            - redis-data:/data
        healthcheck:
            test: ['CMD', 'redis-cli', 'ping']
            interval: 30s
            timeout: 10s
            retries: 5
            start_period: 5s

volumes:
    redis-data:

```

サーバーに`docker`/`podman`がインストール済みであることを確認し、実行する：
```bash
# docker
# up
sudo docker-compose up -d
# down
sudo docker-compose down

# podman
# up
podman compose up -d
# down
podman compose down
```

`docker`/`podman`は不足しているイメージを自動的に取得しに行く。国内でイメージを取得するには科学上网かミラーステーションを経由する必要がある。クラウドサービス事業者が提供するイメージアクセラレーション、あるいは[public-image-mirror](https://github.com/DaoCloud/public-image-mirror)の使用を勧める。

RSSHubをインストールすれば、自デプロイしたインスタンスを通じてコンテンツのルーティングを完了できる。RSSフィードの生成については、ブラウザに公式プラグイン[RSSHub Radar](https://addons.mozilla.org/zh-CN/firefox/addon/rsshub-radar/)をインストールすることを勧める。これは現在のウェブページの内容をスキャンし、利用可能なルートを検出して、対応するRSSフィードを生成できる。
[![RSSHub-Radar.png](https://i.postimg.cc/d11zYfjX/RSSHub-Radar.png)](https://postimg.cc/f3GH7BFj)

個人のインスタンスを使用するには、生成されたリンクのドメインを自デプロイしたインスタンスのアドレスに置き換える必要がある。例えば生成されたRSSフィード：`https://rsshub.app/zhihu/people/activities/61-8-91-53-69` を `http://[ip]:1200/zhihu/people/activities/61-8-91-53-69` に置き換える。

### RSSリーダー
> *Miniflux is a minimalist and opinionated feed reader.*

自デプロイのRSSリーダーには`miniflux`を勧める。あまり派手な機能はなく、*for content for simple*、**Less is more**の哲学思想を完璧に遵循している。

私のサーバーのOSは`Debian`を使用しており、パッケージマネージャから直接インストールできる：
```bash
# add apt source
sudo echo "deb [trusted=yes] https://repo.miniflux.app/apt/ * *" | sudo tee /etc/apt/sources.list.d/miniflux.list > /dev/null

# update apt
sudo apt update

# install miniflux
sudo apt install miniflux
```

`miniflux`はPostgreSQL（バージョン11以上、mysqlではなくpgを使うのは高評価）に依存する。`miniflux`のインストールでminiflux.serviceが自動的に作成され、`systemctl`で管理できる。その設定ファイルは`/etc/miniflux.conf`である。

インストール後は`miniflux`を設定し、nginx sslで`miniflux`サービスをプロキシして安全を確保する必要がある。`/etc/miniflux.conf`を以下のように設定する。其中のpgパスワードとドメインは変更する必要がある：
```conf
# See https://miniflux.app/docs/configuration.html

RUN_MIGRATIONS=1
PORT=18080
DATABASE_URL=user=postgres password=[pwd] dbname=miniflux2 sslmode=disable
BASE_URL=https://[domain]/miniflux
```

`miniflux`へのnginxプロキシを追加する：
```conf
location /miniflux/ {
        add_header Content-Security-Policy upgrade-insecure-requests;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_pass http://127.0.0.1:18080/miniflux/;
        proxy_redirect http://127.0.0.1:18080/ /miniflux/;
        proxy_redirect https://$host/ /miniflux/;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
}
```

最後に`miniflux`の管理者アカウントを作成する。
```bash
# 确保pg正常运行，账号密码已配置，数据库miniflux2已建立
# restart miniflux
sudo systemctl restart miniflux

# create admin user
miniflux -create-admin
Enter Username: ****
Enter Password: ****
```

最後に`https://[domain]/miniflux`にアクセスすれば、`miniflux`を正常に使用できる。`miniflux`内でフィード（RSS, Atom, RSSHub）を追加すれば、購読した内容を`miniflux`で見ることができる。最終的な効果図：

[![miniflux-rsshub.png](https://i.postimg.cc/SKTD4xsP/miniflux-rsshub.png)](https://postimg.cc/bGnQH810)

モバイル端末でアクセスする必要がある場合、ブラウザ以外にサードパーティ製アプリも使用できる。詳細は[Third-Party Applications](https://miniflux.app/docs/apps.html)を参照。
