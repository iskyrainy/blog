# Cloudflare outage on 11.18, 2025

## Three major outages in one month

Following significant service disruptions at AWS and Azure earlier in October, Cloudflare experienced a large-scale outage on November 18 at 11:28 AM. Cloudflare reports that its network handles traffic for a substantial portion of global Internet requests, meaning platforms such as Twitter, ChatGPT, and even network monitoring tools like Downdetector experienced varying degrees of unavailability.

![Cloudflare error](https://cf-assets.www.cloudflare.com/zkvhlag99gkb/3ony9XsTIteX8DNEFJDddJ/7da2edd5abca755e9088002a0f5d1758/BLOG-3079_2.png)

The Cloudflare incident lasted roughly five hours, and engineers published a detailed incident report explaining the root cause and response process.<sup>[1]</sup>

A simplified summary of the three recent outages:
* **AWS — 2025.10.20**
  A concurrency issue triggered unintended clearing of core DNS records, leading to cascading failures across dependent systems.
* **Azure — 2025.10.29**
  Configuration propagation issues caused edge nodes in multiple regions to load invalid or incomplete configurations.
* **Cloudflare — 2025.11.18**
  Incorrect access permissions allowed feature data packages to exceed processing limits, rapidly overwhelming systems and leading to widespread failure.

Although the triggering mechanisms differed, all three incidents exposed how small oversights can scale dramatically in global cloud infrastructures.

## What causes outages?
Service unavailability at cloud providers typically comes from several domains:
1. Physical and infrastructure layer: hardware failure, data center facility issues, network and carrier problems.
2. Software and Platform Layer: software logic bugs, software security vulnerabilities.
3. Human factors: operational error, permission error etc.

Importantly, these three incidents were **not** attributed to cyberattacks or malicious activity — the causes were internal, technical, and operational.


## What can we learn from these incidents?

Although Cloudflare uses the Rust language to ensure absolute data memory safety, which guarantees that Cloudflare will not experience data race failures like AWS, Cloudflare still experienced large-scale outages.
> By the way, don't be silly and argue about Rust's unwrap; that's totally not the point of the problem at all.

The reasons for these three outages seem rather humorous, all stemming from seemingly simple logical errors in hindsight—errors so naive they appear to be made by novice programmers. Is it because the programmers at these major cloud service providers lack skill? Clearly not.

I previously wrote a data import program that daily checks for and updates data files generated by push notifications. The logic was very simple, but I made a remarkably simple and foolish mistake—using an unlocked global variable during import caused a data race condition, which only accidentally triggered after running for over a year.

This was indeed a very, very simple logical error, so much so that I found it hard to believe such a flaw even existed after confirming the bug. However, due to inadequate test design, the bug quietly went live.

Therefore:
- it's crucial to accurately analyze business logic and eliminate logical errors (including data race conditions, deadlocks, unhandled boundary conditions, etc.); 
- rigorous unit and integration testing must be conducted on the code;
